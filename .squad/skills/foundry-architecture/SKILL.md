# Foundry Architecture

## Use When

Selecting or reviewing a Microsoft Foundry application architecture.

## Procedure

1. Capture user experience, capabilities, latency, throughput, cost, traffic, residency, privacy, knowledge, tools, modalities, state, human review, evaluation, observability, deployment, offline, and Azure constraints.
2. Ask in order: does this need AI; direct model invocation; Model Router; Responses API ephemeral agent; Prompt Agent; Hosted Agent; custom Microsoft Agent Framework orchestration.
3. Evaluate Foundry IQ for governed enterprise knowledge, the singular Toolbox for reusable tools, Foundry Skills for reusable procedures, and current first-party Foundry Tools before custom equivalents.
4. Distinguish Foundry Local for on-device/offline use from Foundry Local on Azure Local for Azure Arc/Kubernetes-operated local infrastructure.
5. Prefer supported first-party SDKs and services. Prefer C#/.NET only when support is equivalent.
6. Record rejected alternatives, current evidence, uncertainty, security, evaluation, operations, and rollback requirements.

An architecture decision proves each component earns its place, cites fresh evidence for volatile claims, and gives downstream owners testable contracts.
